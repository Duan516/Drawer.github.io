# 2026-08-20 工作日志

## projects 页 fun/academy 卡片过长 —— 根因与修复（已 Puppeteer 实测验证）

### 现象
projects 页 fun、academy 分类卡片特别长（竖向封面图把卡片撑高），work 区正常。

### 排除项（已验证非原因）
- `_sass/_base.scss` `.projects .card img` 的 `aspect-ratio:3/2; object-fit:cover` 规则正确，编译产物 main.css 含该规则，服务端返回一致，无其它 img 规则覆盖。
- 猜城记封面是竖版（1385×2612）只是表象，根因是规则没作用到，不是图片本身。

### 真正根因（两处，都在 `_pages/projects.md`）
1. **多余的 `</div>`**：文件两个竖向（非 horizontal）分支里，各多了一个 `</div>`——`<div class="row">` 只开了 1 个，却用 2 个 `</div>` 去关。这个多余的 `</div>` 把外层 `.projects` 容器在 work 之后提前闭合，导致 fun/academy 被渲染到 `.projects` 容器之外 → `.projects .card img` 选择器够不到它们 → 封面按原图比例显示（竖版图撑高）。
   - git HEAD 原始版本竖向分支只有 1 个 `</div>`，是后续某次编辑多加的。
2. **kramdown 转义 `<h2>`**：`{% for category %}` 循环里生成的 `<a id="x"><h2>x</h2></a>`，只有第一次（work）正常，后面被 kramdown 当成段落内文本转义成 `&lt;h2&gt;`，分类标题显示成纯文本。

### 修复（已应用到 `_pages/projects.md` 并验证）
- 删除两个竖向分支里多余的 `</div>`（即 `{% endfor %}` 后、紧跟 `{% endif %}` 之前那个 2 空格缩进的 `</div>`）。
- 用 `{::nomarkdown}` / `{:/nomarkdown}` 把整块 Liquid+HTML 包裹起来，禁止 kramdown 解析，分类标题正常渲染（3 个正常 h2、0 个转义）。
- `<a id="category">` 上的 `markdown="0"` 可留可删，无影响。

### 验证结果（Puppeteer 读真实 DOM）
work/fun/academy 三个区卡片均 `aspectRatio=3/2 / objectFit=cover / height=158px / inProjects=true`，标题均正常。修复完成。

### 教训
- al-folio 的 projects.md 调试优先查 HTML 标签平衡（div 配对），再查 kramdown 解析；别先怀疑 CSS 或图片。
- 验证 HTML 结构用浏览器真实 DOM（Puppeteer）比 python 字符串计数可靠——后者易因 `class="projects"` 偏移或注释匹配出错。
- 本地 jekyll serve 会实时重编译（约 6s），curl 4400 与读 _site 文件一致。
